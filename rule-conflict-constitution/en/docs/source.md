# Source notes

## Where it is adapted from

The AI Collaboration Constitution v1.0 is adapted from the constitution NWC-1.7 (2026-11-01) of the Novel Writing Workshop. The Workshop's repository is public: <https://github.com/rumpelpalmour757-lgtm/novel-workshop>. The LICENSE in its root folder is the MIT license, with the copyright line Copyright (c) 2026 Celeste; this repository's [LICENSE](../../LICENSE) names the same copyright holder.

The files used are these, from the full package the Workshop released publicly. They are not in the file tree of the Workshop's repository; they are in `novel-workshop-commercial-r5.57.zip`, the download attached to release [r5.57](https://github.com/rumpelpalmour757-lgtm/novel-workshop/releases/tag/r5.57) on the Workshop's releases page (when this was written, the same file was also in the root folder of the Workshop's repository). The paths below are under the skill folder `skills/novel-workshop/` once the package is unpacked:

- `CONSTITUTION.md`: the full text of constitution NWC-1.7.
- `assets/constitution-rules.json`: the constitution's register, which records the module, script and test each principle lands in.
- The section "规则打架时" ("When rules conflict") in `references/continuity.md`: the detailed practice for the five resolution steps, checking before admitting, and the format of the conflict register.
- The sections "交付状态" ("Delivery status") and "阶段与权限" ("Stages and permissions") in `references/quality-loop.md`: the four statuses and the permission rulings.
- `assets/rule-conflicts-template.json`: the conflict register template.
- `scripts/rule_register.py`: the script that checks the conflict register, and its two tests in the `tests/` folder at the root of the unpacked package.

The section "Added or expanded in the adaptation" below says which practices the Workshop also has, and it also mentions the entry page of the Workshop's skill, `SKILL.md`.

The Workshop is for writing novels; the terms, examples and means of enforcement in its constitution all revolve around writing novels. Only the parts that do not depend on any industry are taken here, reworded so that anyone working with AI can use them, and the examples are all replaced with newly written, neutral work scenarios.

## What was not carried over, and why

- **CON-011 分场张力与正文具象 (scene tension and concrete prose), CON-012 先备料，后落笔 (prepare the material first, then write).** These two are specific to writing novels and make no sense in other work. This constitution's C11 and C12 are two separate, newly written principles, numbered on from C10, and have nothing to do with these two.
- **The "hard" and "soft" classification and each principle's "landing point".** The Workshop calls principles guarded by program checks or tests "hard", and the landing points point to the Workshop's own modules, scripts and tests. The general version has none of those programs, and copying them over would make people think a program guards them. Here they are replaced by each principle's "How it is applied", written truthfully: in this repository only the conflict register is checked by a program, and the rest relies on people and the AI following it.
- **The constitution's machine-readable register (`constitution-rules.json`).** It records which script and which test enforce each principle in the Workshop; the general version has nothing that corresponds to it.
- **The stage summary** (DRAFT, READY_FOR_AUTHOR, AUTHOR_ACCEPTED and several exception stages). In the Workshop a script works it out from the four statuses. The general version has no such program, so only the four statuses and the permission rulings are kept, to avoid one more set of terms that people would have to work out by hand.
- **The revision history and the words quoted in it.** This repository's changelog is newly written from v1.0; see [CHANGELOG.md](../../CHANGELOG.md) (in Chinese).
- **Practices tied to the Workshop's scripts.** For example, the command used when skipping review, the command that checks the delivery files before delivery, and the steps for updating the fact ledger and the learning records when acceptance is withdrawn. Only the general meaning is kept: record truthfully, do not write conclusions after the fact, and do not delete the original records.
- **The Workshop's examples.** The novel-writing examples in "When rules conflict" in the continuity reference and in the register template are all replaced with newly written, neutral examples.
- **The checking script's support for old digests.** The Workshop's script also accepts old digests from an early version that were computed over bytes; the new repository has no old registers, so it does not need this.

## The checking script and the template

- [scripts/conflict_register.py](../../scripts/conflict_register.py) is rewritten from the Workshop's `rule_register.py`; the meaning of its three commands `check`, `list` and `collide` is unchanged. The terms are changed as in the table above; the help text and error messages are in Chinese, and the JSON keys in English. In a few places it is stricter than the original script, or says things more clearly: only LF, CRLF and a lone CR count as line breaks; the rule side's original wording is looked for only in the original text after `<!-- 原文开始 -->` (the first one, if there are several); superseded and pending sources that have a `file` are checked just the same; it adds `warnings` (saying what was not checked) and `sources.digests` (the current digest of each local source); duplicate keys in the same object are reported; the decision sheet from `list` gains a heading line and Chinese wording; `collide` adds `unreadable_texts` and `--ignore-case`. A few more are new in this version: the marker line is also accepted in its English form `<!-- original text begins -->`, and when both forms appear, the first one in the file counts; `NaN`, `Infinity`, numbers that overflow and unpaired escapes such as `\uD800` in the register are errors; unknown keys, local sources that were read without a `sha256`, and sources with no local file that have a `sha256` get reminders in `warnings`; a decided `exception` can only be decided by the principal; a `closed` item that has `decided_by` is checked by the rules for `decided`; `texts` written as `null` counts as not written; line breaks in values become "／" in the decision sheet; an empty `--texts-root`, and words to search for that have bytes that cannot be decoded as UTF-8, are usage errors with exit code 2; the rule side gets a new optional `strength` (`must` or `should`), whose value `check` checks and which the decision sheet from `list` shows.
- The Workshop's register is called `rule-conflicts/1`; the format here is different (for example, `decided_by.who` takes `principal` or `ai`, not `author` or `workshop`), so it gets a new name, `conflict-register/1`. A Workshop register run through this script gets only a report that `schema` is wrong from `check`, `list` and `collide`, and nothing further is checked.
- [templates/conflict-register.json](../../templates/conflict-register.json) is rewritten from the Workshop's `rule-conflicts-template.json`, with the example replaced by a newly made-up project translating a manual.
- The scenarios in [examples/help-center](../examples/README.md) and [tests/](../../tests/) are newly written, not copied from the Workshop's examples or tests.

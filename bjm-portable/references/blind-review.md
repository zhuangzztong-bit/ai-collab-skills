# 准备匿名对照材料

为 [BJM §11.8 的同题对照](bjm-v3.2.md#118-方法维护与同题对照)准备材料时，用同一份题目、资料和验收条件分别执行两版方法，保存实际产出。先逐项核对硬约束和回归。若要用留出题验收，在调试前冻结题目和评判标准，候选定下来后再用留出题跑两版。

从迁移包根目录运行以下命令。输入是 UTF-8 文本，`task.txt` 写共用的任务要求和评分标准。参数里的 `runs/current`、`runs/proposed` 只是示例，换成实际可能暴露版本身份的路径、标签和标记。每个标记用一次 `--identity-marker`。

```bash
python3 scripts/blind_review.py baseline.txt candidate.txt \
  --brief task.txt --key-out manager-key.json --packet-out reviewer-packet.json \
  --identity-marker runs/current --identity-marker runs/proposed
```

## 两个输出文件

- `reviewer-packet.json` 是交给审查者的材料，只包含共用说明和随机分配为 A、B 的两份产出，原文照旧保留。`manager-key.json` 记下 A、B 各是哪一版，以及材料文件的 `packet_sha256`。
- 两个文件都必须是还不存在的新文件，已经存在时脚本拒绝运行，不改动原有文件。脚本出错退出（退出码不是 0）时，会删掉这一次新建的文件，查明原因后照原命令重跑即可；进程被强行终止时来不及删，要自己删掉留下的文件再重跑。
- 每位审查者可以单独准备一份，每次换新的材料文件名和映射文件名。每次运行都重新随机分配 A、B。
- 不加 `--packet-out` 时，材料写到标准输出，这是 v1.5 的用法，仍然可用。这时如果用 shell 的 `>` 保存，shell 在脚本运行前就会清空或新建目标文件，脚本失败时会留下一个空文件或者被清空的旧文件；Windows PowerShell 5.1 的 `>` 还会改写编码，保存下来的文件和 `packet_sha256` 对不上（这一点依据 PowerShell 的已知行为，没有在 Windows 上实测）。所以建议用 `--packet-out`；用标准输出时，只有退出码为 0，保存下来的材料才算有效。反过来，退出码为 0 也不能说明接收的一方收全了：管道另一头的程序提前退出时，材料小于管道缓冲区的话，脚本察觉不到。交出之前，要按下文的方法核对 `packet_sha256`。

## 交给审查者和汇总

- 命令成功后，把 `reviewer-packet.json` 交给隔离上下文的审查者。
- `manager-key.json` 留给负责汇总结论的人，放在审查者的工作目录和上下文之外。文件权限不能代替隔离：在 Linux 上脚本把它建成只有本用户可读写（macOS 按同样的规则，没有实测），但和审查者同一账户的程序照样能读；Windows 上这个设置不限制读取（依据 Python 的文档，没有在 Windows 上实测）。
- 审查结论先锁定，再按映射文件对应版本。保留材料原件，对照映射里的 `packet_sha256`，避免把一轮的结论解读成另一轮。可以用 `python3 scripts/workflow.py fingerprint reviewer-packet.json` 计算，结果应当和映射文件里的 `packet_sha256` 相同。

## 脚本检查什么

- 检查的范围是共用说明和两份产出。要找的标记有三类：两份产出的完整文件名（共用说明的文件名不算）、命令行里原样写的两份产出的路径，以及每个 `--identity-marker`。
- 比较时不分大小写，全角和半角视为相同，斜杠和反斜杠视为相同，连续的斜杠当成一个，路径里的 `./` 忽略，零宽字符和 BOM 这类不可见的格式字符忽略。正文还会在按网址编码（例如 `%2F`）解码之后、以及去掉全部空白之后各查一遍。标记首尾的空白和斜杠不参与比较。所以 JSON 里转义过的路径（例如 `C:\\runs\\current`）、`runs\/current`、全角的 `ｒｕｎｓ／ｃｕｒｒｅｎｔ` 和中间断了行的路径，都按同一个标记处理。
- 标记按片段匹配，出现在一个词的中间也算命中，宁可多拦。为了少误拦，产出所在的目录、文件名的主干和文件名里的版本号不会自动当成标记，需要时用 `--identity-marker` 另外登记，例如 `runs/current`、`v1.5`。反过来，文件名太通用时（例如 `out.md`），产出里正常提到这个名字也会被拦；名字太短时（例如 `a`），几乎所有文本都会被拦。这时把两份产出复制成中性的文件名再准备，例如 `output-1.txt` 和 `output-2.txt`。
- 查不到的写法包括：HTML 实体、Base64 这类其他编码，长得像斜杠的其他字符，改写过的措辞，以及没有登记的路径和标签。
- 命中任意一个标记时，退出码为 1，不输出材料，也不新建任何文件。报错只写出是哪一份输入（`brief`、`baseline` 或 `candidate`），不写出是哪个标记。此时先私下核对线索，必要时另做一份评审副本，保留原始产出。
- 空文件、只有空白或不可见字符的文件，以及不是 UTF-8 的文件，都会被拒绝，报错写明是哪一份输入。

## 交出之前

- 两份产出的换行符（CRLF 或 LF）、开头的 BOM 或末尾换行的个数不一致时，脚本照常生成材料，不改原文，只在标准错误里提示一句；标准错误已关闭或写不进去时不提示，材料和退出码不受影响。审查者能看到这些差异，它们可能暴露是哪一版流水线的产出，要不要先统一格式另做副本，由准备材料的人决定。
- 交给审查者之前，人工检查剩下的线索，例如措辞、附件元数据和没有登记的路径。附件和非文本内容需要另行准备。脚本只做材料隔离，实际评分、硬约束验收和采纳继续按 BJM 记录。

参考了[达尔文 v3.0.0 的实跑盲评](https://github.com/alchaincyf/darwin-skill/releases/tag/v3.0.0)和 [v3.0.1 的路径泄露修复](https://github.com/alchaincyf/darwin-skill/releases/tag/v3.0.1)。达尔文的做法是把材料里的相对路径改写掉；BJM 是独立实现，保留原文，命中已知标记时停止准备。
